# Company important documents

The thesis company page has an Important documents section for companies with a substantive current thesis card. Documents are shared across analysts. Read-only accounts can view saved summaries; analysts and admins can refresh them.

The section is also visible when the signed-in user has no personal thesis and a colleague owns the company's thesis. Switching to that colleague's thesis keeps a single documents section visible.

Refresh retrieves the complete available NSE company announcement history and automatically follows a persisted review queue to completion with `gpt-5.6-luna`. There is no 90-day window, 100-row read cap, or five-document-per-click limit. Each bounded request advances a small concurrent batch; the browser continues automatically. A database lease coordinates tabs and serverless instances. Closing a tab preserves completed summaries and the checkpoint; Refresh resumes it.

Routine notices are excluded before analysis; Luna makes the final materiality decision. Each material document has a category, a short takeaway, an expandable summary and the source PDF link. Duplicate PDF URLs reuse cached analysis. Failed documents do not prevent later or older filings being reviewed, and remain explicitly visible for retry. Page loads read saved summaries and progress without calling AI. The displayed date range describes the available NSE archive, not a guarantee of pre-NSE-listing or BSE-only coverage.

NSE-listed companies and trusted NSE HTTPS PDF URLs are supported in this version. Companies without an NSE ticker receive an explanatory message. Retrieval or summary failures retain saved work and show warnings. The existing announcement collector includes substantive thesis-card companies; PDF summaries are generated by Refresh documents.

## Deployment prerequisite

Apply `web/drizzle/0035_company_document_summaries.sql` before deploying dependent code. It adds a nullable JSONB document summary to `valuation.announcements`. Existing short announcement summaries remain separate.

Production Vercel builds run `scripts/migrate-company-documents.mjs` before compiling the application. The script checks the expected Neon production endpoint, applies migration 0035 idempotently with bounded lock/statement timeouts, and verifies the column type. A failure stops the deployment. Other environments skip this production-only step. Production credentials remain inside Vercel.

For the user-authorized live BALUFORGE backfill, a temporary production build variable `DOCUMENT_HISTORY_VALIDATE_COMPANY=BALUFORGE` enables `scripts/validate-company-document-history.mjs`. It exercises the built application's authenticated API using protected production credentials, reviews real filings with Luna, saves production summaries, and logs coverage/counts without credentials. Remove the temporary variable after validation. Normal deployments skip this paid integration test. Queue/checkpoints use the existing `valuation.app_meta` store; no new schema migration is needed.
